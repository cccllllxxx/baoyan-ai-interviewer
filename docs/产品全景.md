# 保研复试 AI 陪练 · 产品全景

> 2026-08-30 项目挑战日整理。分四块：已实现的核心闭环、fork 不走的差异化、刻意不做的取舍、未来设想三档路线图。
> 本文同时是 Product Memo 的底稿。
>
> **一句话产品哲学**：目的不是把面试者变成 AI，而是帮他发现自己的特质、更像自己地呈现。诊断报告的正面是「你的特质 · 怎么更像你自己」，背面才是「被问穿的地方」——前者锚定人设，后者防穿帮。

---

## ① 核心闭环（已上线，全链路真机验证）

用户走完一条完整链路，7 步：

| # | 步骤 | 说明 |
|---|------|------|
| 1 | 选项目方向 | 12+ 预设保研项目（光华 MIM/MFin、经院、国发院等）+ 自定义 |
| 2 | 复试结构 | 界面展示 4 个练习模块（简历深挖已开放；职业规划/英语/时事抽题为预告灰度）；面试本身固定 6 环节：自我介绍与动机 → 科研项目贡献 → 专业基础与方法 → 研究设计/行业判断 → 热点立场 → 综合抗压 |
| 3 | 生成人才画像 | 「这个方向要什么样的人」：4 条标准 + 3 条淘汰项 + 最爱追问的点，注入面试官 prompt 作评判依据（来自受访者C的洞察：复试本质是人岗匹配） |
| 4 | 上传简历 | 支持 txt / docx / pdf（unpdf 解析），提取后供考官逐段咬 |
| 5 | 剧场式 3 考官复试 | 主考官（环节①⑥）+ 研究背景考官A（②③）+ 业界背景考官B（④⑤）；剧场式开场「请进，坐…」；环节自然交接不报幕；自适应追问 + 难度递增；7 类攻击清单（A 经历真实性、B 科研细节、C 理论框架、D 因果识别、E 行业理解、F 空话黑话、**G 对照性陷阱题**）；**6 环节走完后进入反问环节**（考官问「你有什么想问我们的吗」并简短回应，再收尾） |
| 6 | 诊断报告 | 四维评分（问题意识 / 论据支撑 / 表达结构 / 抗压诚实度）+ **「你的特质 · 怎么更像你自己」**（one_liner + 你真正有的优势 + 怎么当锚 + 会被一眼看穿的地方 + 该呈现的人设）+ 逐题复盘（被问穿的地方 + 致命原因 + 该补的知识点）+ **知识地图 study_map**（缺什么知识模块 + 可直接检索的关键词 + 资源类型与检索路径）+ **反问环节评价**（逐条加分/减分 + 考官视角 + 下次该问什么）+ next_steps |
| 7 | 演示兜底 | 无 API key 时自动降级 mock 数据，公网演示不断链 |

## ② 差异化护城河（fork 不走的部分）

闭环本身可以 fork，护城河在**垂直深度 + 访谈驱动**，每一项都有出处：

| 能力 | 依据 |
|------|------|
| 人才画像注入评判 | 受访者C：复试是「人岗匹配」，先明确要什么人再评 |
| 咬死经历真实性 | 受访者Y / 假设 H2：最怕科研细节被逐层追问 |
| 照妖镜，不是提词器 | 教授能识破 AI 背稿（引用错误/概念混乱/句式机械）→ 反着设计 |
| 学术型 / 专业型分轨 | 假设 H3：学硕直博怕研究设计，专硕怕实习产出深挖，混做必浅 |
| 对照性陷阱题（攻击清单 G） | 区分真理解与背稿的最快手段：构造表面冲突情境要求当场解释 |
| **你的特质 · 怎么更像你自己** | 落实产品哲学：不是变成 AI，是发现自己的特质、更像自己地呈现。从本场对话/简历真实素材提炼，禁编他没有的特质（呼应「照妖镜」正面） |
| **反问环节评价** | 真实复试末尾必有「你有什么想问我们的吗」，好反问能赢得考官青睐——产品补齐这一步并逐条评价加分/减分 |
| 知识地图（不给话术） | 思考点008：清北考生不缺话术，缺「自己的东西站不站得住」 |
| 访谈驱动迭代 | 5 份微信访谈原话 + H1–H7 假设文档，见 `docs/` |

### 关于「评价后给的可执行改进方案到底有什么」

诚实回答（回应评审/用户质询：「这个痛点人人能找，你们到底给了什么」）：

- **给了的**：① 知识地图 study_map——缺什么知识模块 + 可直接拿去搜索引擎用的关键词 + 资源类型与检索路径（如「找一篇用 XX 方法的实证论文精读其稳健性部分」）；② 被问穿的地方逐条给出「背后缺的知识点 + 学习方向」；③ 你的特质——把改进从「补短板」扭向「扬长 + 真实呈现」。
- **没给、也没承诺给的**：可直接点的资料链接、策展过的题库。原因有三：① **数据纪律**——无访谈/权威出处的具体 URL 一律不写死，禁止 AI 编造书名课程名（这是刻意的，不是漏做）；② 没有沉淀过人工策展的资源库（保研垂直的优质资料极度分散、时效性强，AI 生成链接几乎必错）；③ 时间盒。
- **路线图里怎么补**：下一步先做「可检索关键词 → 人工策展的资料/题库」的最小版（先 1–2 个高频模块，人工核对后再上链接），不靠 AI 现编。

**与开源竞品的差异**（实查过仓库）：
- Sean-9/MockInterview：Claude Code prompt skill，JD 求职向，无保研垂直、无产品 UI；其「信心盲区」点子已记入下一步吸收。
- Marssssss/OneAI：通用 Agent 框架，面试演练只是预设之一，非垂直产品。

## ③ 刻意不做（取舍，写进 Memo 反而加分）

| 不做 | 理由 |
|------|------|
| 语音 / 停顿 / 情绪分析 | 痛点未验证，时间盒放不下 → 留路线图 |
| 理工科保研 | 咬点是实验细节，与经管社科完全不同，混做必浅 |
| 给背稿话术 | 与「照妖镜」哲学正面冲突，且教授能识破 |
| 编造数据 / 引用 | 报告禁 URL / 书名杜撰，无访谈出处的数值不写死 |
| 真人陪练撮合 | 规模化、成本、合规三重不成立 |

## ④ 未来设想 · 三档路线图

### 下一步（挑战后立刻做，写入 Memo「Next Steps」）
- **真人测试 5 人+**：方案本身未经真人验证是当前最大短板
- **信心盲区**：作答前自评信心 vs 实际评分的落差可视化（吸收自竞品）
- **自定义项目冷启动**：选自定义项目时，AI 先反过来追问用户 3–5 个问题收集项目信息（面试形式、考官构成、历年风格、偏好），替代目前的手填「项目背景」框，让 AI 更准确地扮演该项目的考官
- **可检索关键词 → 人工策展资料/题库**：先把 1–2 个高频模块（如因果识别/稳健性检验）的优质资料人工核对后上链接，不靠 AI 现编
- **反背稿检测升级**：句式机械度分析、引用错误模拟
- **项目库扩充**：预设 12+ → 30+，覆盖清北人复交主流项目

### 中期（3–6 个月）
- 语音模式：双 AI 轮流对打 + 语音 live 评测（小红书灵感，需先验证需求）
- 错题本 + 弱项复训：把 study_map 闭环成「练 → 测 → 补 → 再测」
- 英语口语环节专项（经管保研英语面占比高）

### 远期（方向性，不承诺）
- 真考官 / 上岸学长众包提问库：画像与陷阱题从 AI 生成走向真实沉淀
- 模拟排名：同项目方向下的相对水位
- 语音停顿 / 情绪压力分析
- 从单场陪练到「保研全程诊断」：夏令营前中后三次报告纵向对比
